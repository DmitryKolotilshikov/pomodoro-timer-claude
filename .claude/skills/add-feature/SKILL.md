# Добавление фичи в Pomodoro

Фича: $ARGUMENTS (если пусто — бери описание из последнего запроса пользователя).

Проект маленький и держится на нескольких договорённостях (одна функция `render()`, перекраска через `--accent`, отсчёт по дедлайну). Фича, которая их обходит, «работает», но ломает следующую фичу. Поэтому главная задача — вписаться в то, что уже есть, а не просто сделать, чтобы кнопка нажималась.

## 1. Разберись, что именно просят

- Если в запросе есть настоящая развилка, от которой зависит результат (куда поставить кнопку, сохранять ли настройку между перезагрузками, должна ли фича влиять на игру), — задай один короткий вопрос со своим вариантом по умолчанию. Мелочи (точный оттенок, текст подсказки) решай сам и упомяни в отчёте.
- Если фича конфликтует с архитектурой (например, «пусть таймер считает тиками»), скажи об этом прямо и предложи вариант, который вписывается.

## 2. Прочитай код, который затрагиваешь

CLAUDE.md уже в контексте — там архитектура. Дальше читай по факту:

- `index.html` — разметка и **все** стили (в одном `<style>`); правила вёрстки — `.claude/rules/ui.md`, прочитай их, если трогаешь HTML/CSS.
- `script.js` — таймер, состояние, звук, кнопки.
- `game.js` — мини-игра; читай, если фича касается игры или её оверлея.

## 3. Реализуй, соблюдая договорённости проекта

Таймер (`script.js`):
- Новое состояние — модульная переменная рядом с остальными; после каждого её изменения вызывай `render()`. Всё, что видно на экране, обновляет `render()`, а не обработчик кнопки.
- Новый режим — запись в `MODES` (длительность, подпись, цвет через CSS-переменную).
- Время — только через `endsAt`/`Date.now()`; признак «идёт» — `tickId !== null`.
- Звук — через `playNotes`, без аудиофайлов; `audioCtx` может быть `null` до первого «Старт».
- Новая кнопка — `id` + запись в `els` + `addEventListener` внизу файла, рядом с остальными.

Стили (`index.html`):
- Цвета — переменные в `:root`; перекраска интерфейса — через `--accent`. Из JS выставлять только CSS-переменные на `:root` и классы, никаких inline-стилей.
- Размеры в `rem`, кнопки наследуют общий стиль `button` (не переопределяй `font-size`/`padding` — сломается одинаковая высота).
- Новая анимация автоматически отключится под `prefers-reduced-motion`; если анимация в JS (canvas, `requestAnimationFrame`) — учти `reducedMotion` сам.

Игра (`game.js`):
- Код только внутри IIFE; цвета читай из CSS-переменных каждый кадр, как уже сделано, чтобы игра перекрашивалась вместе с таймером.

Общее:
- Без зависимостей, CDN и сборки — проект открывается через `file://`.
- Тексты интерфейса — на русском, в тоне остальных кнопок.
- `localStorage` — в `try/catch` (как в `game.js`), ключ с понятным префиксом.
- Комментарии — как в окружающем коде: коротко и по-русски, объясняют «почему».

## 4. Проверь в браузере

Открой `file://<абсолютный путь>/index.html` через Playwright MCP (`browser_navigate`, затем `browser_snapshot` / `browser_click` / `browser_evaluate` / `browser_take_screenshot`). Проверь:

1. Консоль без ошибок (`browser_console_messages`).
2. Сама фича работает — пройди её сценарий кликами, а не только взглядом на разметку.
3. Не сломалось соседнее: Старт → Пауза → Сброс, кнопка «Цвет», открытие и закрытие игры.
4. Скриншот итогового вида — посмотри на него сам: кнопки одной высоты, ничего не вылезло, неон на месте.

Ждать 25 минут не нужно: `script.js` — классический скрипт, его `let`-переменные доступны из `browser_evaluate`. Например, `endsAt = Date.now() + 2000` при запущенном таймере — и через пару секунд отрезок закончится.

Если Playwright недоступен — открой страницу через `open index.html`, честно напиши, что проверить поведение автоматически не удалось, и перечисли, что пользователю стоит прокликать.

## 5. Обнови документацию, если поменялась архитектура

Новый файл, новая переменная состояния, новый ключ `localStorage`, новая связь JS → CSS — добавь строку в раздел «Pomodoro: архитектура» в `CLAUDE.md`. Косметику (новый цвет, текст) не документируй.

## 6. Не коммить

Пользователь сам управляет историей git. Оставь изменения незакоммиченными и в отчёте скажи, какие файлы изменены.

## 7. Отчёт

Коротко, по-русски, на «ты», без преувеличений:

- **Что сделано** — 1–3 предложения, как этим пользоваться.
- **Файлы** — какие изменены.
- **Проверка** — что проверено в браузере и что нет (если что-то не удалось проверить или работает с оговоркой — так и скажи).
- **Решения** — что выбрал сам, где был выбор.
- **Идеи** — 1–2 возможных продолжения, если есть что-то действительно полезное.
